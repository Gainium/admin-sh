# 002 — `CORS_ORIGIN` accepts commas and/or whitespace

## §1. Definition (behaviour today)

docker-sh passes one `CORS_ORIGIN` value to both admin-sh and the main-app
api. admin-sh splits it only on commas; main-app splits it only on single
spaces.

- §1.1 Space-separated (`http://localhost:7500 http://192.168.1.50:7500`):
  admin-sh treats the whole value as ONE origin and sends the whole string
  back as `Access-Control-Allow-Origin` to every request. Browsers reject a
  header that lists several origins, so every Admin Center call fails from
  every origin.
- §1.2 Comma-separated: works here, but main-app's space-only split makes
  the api send no CORS header at all — so no single format works on both
  services.

## §2. Evidence

Real admin-sh `dist/index.js` started with each value, requests sent with
`Origin: http://localhost:7500` / `http://192.168.1.50:7500`:

| CORS_ORIGIN format | `Access-Control-Allow-Origin` returned          |
|--------------------|-------------------------------------------------|
| single             | `http://localhost:7500` (unchanged by this fix) |
| space              | `http://localhost:7500 http://192.168.1.50:7500` for both origins → blocked |
| comma / mixed      | the matching origin → ok                        |

## §3. Assumption (root cause)

The parser in `src/index.ts` is `includes(',') ? split(',') : whole string`.
Whitespace is never a separator, so a space-separated list reaches `cors`
as a single string origin, which `cors` echoes verbatim.

## §4. Desired behaviour

- §4.1 The value is split on any run of commas and/or whitespace, each entry
  trimmed, empty entries dropped. Comma, space and mixed lists all yield
  every listed origin.
- §4.2 A value with exactly one origin is still passed to `cors` as a plain
  string, exactly as today (`cors` then answers every request with that
  origin — unchanged for existing single-address installs).
- §4.3 Unset / empty `CORS_ORIGIN` still registers no CORS middleware.
- §4.4 main-app applies the same split (`split(/[\s,]+/).filter(Boolean)`)
  in its server; there a single value was already a one-element array, and
  still is.
